# Coinboard — 바이낸스 코인 시세 대시보드

비트코인(BTC/USDT)과 이더리움(ETH/USDT)의 현물 시세를 보여 주는 첫 번째 웹 프로그램입니다. HTML, CSS, JavaScript만 사용하며 회원가입, API 키, 별도 패키지 설치가 필요 없습니다.

## 실행 방법

### GitHub Pages로 배포하기

실제 저장소 이름은 `crypto-dashbord`입니다(`dashboard`와 철자가 다릅니다). 이 저장소를 기준으로 설정하세요.

1. 준비된 Pull Request의 변경 내용을 확인하고 **Merge pull request → Confirm merge**를 눌러 `main`에 반영하세요. 병합 전에는 공개 사이트가 배포되지 않습니다.
2. 저장소에서 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택하세요. **Deploy from a branch** 대신 Actions를 선택해야 아래의 파일 제외 설정이 적용됩니다.
3. 저장소의 **Actions** 탭에서 **Validate and deploy GitHub Pages** 실행을 확인하세요. Pages 설정 전에 실행되어 실패했다면, 실패한 실행의 **Re-run all jobs**를 누르세요. 또는 해당 워크플로의 **Run workflow**에서 `main`을 선택해 실행할 수 있습니다.
4. 실행이 초록색으로 완료되면 **Settings → Pages**의 사이트 링크를 여세요. 기본 주소는 `https://niche086.github.io/crypto-dashbord/`입니다. 실제 배포 완료 전에는 이 주소가 작동한다고 확인한 상태가 아닙니다.
5. 두 코인의 카드, **최신 시세 연결됨**, 가격·거래량, 마지막 갱신 시각을 확인하고 약 30초 후 시각이 갱신되는지 확인하세요. 화면이 오래된 경우 **Ctrl+Shift+R**로 다시 불러오세요.

회사 PC에서 로컬 서버를 계속 실행할 필요가 없습니다. 사이트 방문자의 브라우저가 바이낸스에 직접 요청하므로 방문자 네트워크의 API 접근·CORS·지역 제한은 그대로 적용됩니다. GitHub Pages는 API 프록시 역할을 하지 않습니다.

배포 워크플로는 `index.html`, `style.css`, `script.js` **세 파일만** 업로드합니다. README, 미리보기 복사본, Python 도구, 테스트 파일, 스크린샷, Git 메타데이터는 사이트에 포함되지 않습니다. 세 파일의 상대 경로는 GitHub Pages의 `/crypto-dashbord/` 하위 경로에서도 유지됩니다. npm 설치나 빌드 도구는 필요 없습니다.

API 키·비밀번호·개인 토큰을 사이트에 넣지 마세요. 배포는 GitHub가 실행 시 제공하는 자동 인증과 최소한의 Pages 권한을 사용하며, 별도의 개인 토큰을 저장할 필요가 없습니다. `.gitignore`는 흔한 로컬 비밀 파일의 커밋을 막지만 모든 민감 정보 누출을 탐지하는 도구는 아닙니다.

Pull Request에서는 파일 준비와 문법 검사를 수행하며 배포하지 않습니다. `main`에 병합한 뒤에는 후속 변경을 push할 때마다 자동 배포됩니다. 저장소 관리자 권한 또는 조직 정책에 따라 Pages/Actions 설정이 제한될 수 있습니다.

### 웹 미리보기에서 디자인이 보이지 않을 때

**`preview.html`을 열어 주세요.** 원본과 동일한 CSS와 JavaScript가 파일 안에 들어 있어, HTML 파일 하나만 전달하는 미리보기에서도 별도의 CSS·JS 파일 경로가 필요 없습니다. 다운로드한 이 파일 하나를 브라우저에서 열어도 됩니다. API 통신에는 인터넷 연결이 필요합니다.

`index.html`은 같은 폴더의 `style.css`, `script.js`를 상대 경로로 불러옵니다. HTML만 복사하거나 다른 두 파일을 제공하지 않는 미리보기에서는 디자인이나 갱신 기능이 빠질 수 있습니다. 확인한 로컬 웹 서버에서는 세 파일이 정상 응답했습니다. 사용자의 미리보기 URL에서는 직접 확인하지 못했습니다.

미리보기 서비스가 JavaScript 실행 또는 외부 API 통신 자체를 금지한다면 단일 HTML도 그 제한을 해제할 수 없습니다. 이때는 파일을 다운로드하여 일반 브라우저로 열거나 아래 로컬 웹 서버를 사용하세요.

원본 파일을 수정한 후에는 프로젝트 폴더에서 `python3 tools/build-preview.py`를 실행해 `preview.html`도 갱신하세요(Windows: `py tools/build-preview.py`). 이 명령은 실행 위치와 관계없이 원본 파일이 있는 폴더를 기준으로 동작합니다.

### 일반 크롬에서 로컬 웹 서버로 실행하기 (권장)

회사 PC에서 실행하는 방법입니다. API 키나 Node.js, npm은 필요 없습니다. Python 3만 필요합니다.

1. 제공된 최신 ZIP 파일을 내려받아 **모두 압축 풀기**를 선택하세요. ZIP 안에서 파일을 직접 열지 마세요. GitHub의 ZIP은 이번 변경이 GitHub에 반영된 후에만 최신 버전입니다.
2. 압축을 푼 폴더에 `index.html`, `style.css`, `script.js`가 있는지 확인하세요.
3. **Windows:** 그 폴더를 파일 탐색기로 연 뒤 위쪽 주소창에 `cmd`를 입력하고 Enter를 누르세요. 다음 명령을 입력합니다.

   ```bat
   py -m http.server 8000 --bind 127.0.0.1
   ```

   `py`를 찾을 수 없다고 나오면 `python --version`으로 Python 설치를 확인하세요. 설치되어 있다면 위 명령의 `py` 대신 `python`을 사용할 수 있습니다. Python이 없다면 회사의 소프트웨어 설치 정책에 따라 Python 3 설치를 요청하거나 진행하세요.
4. **macOS / Linux:** 터미널에서 압축을 푼 프로젝트 폴더로 이동한 후 실행하세요.

   ```sh
   python3 -m http.server 8000 --bind 127.0.0.1
   ```

5. 터미널을 열어 둔 상태에서 일반 크롬 주소창에 **`http://127.0.0.1:8000/index.html`**을 입력하세요. Codex 내부 미리보기 대신 회사 PC에서 띄운 이 주소를 사용합니다.
6. 종료할 때는 서버를 실행한 터미널에서 **Ctrl+C**를 누르세요.

8000 포트가 사용 중이라는 오류가 나면 명령의 `8000`을 `8001`로 바꾸고 크롬에서도 `http://127.0.0.1:8001/index.html`을 여세요. 폴더 목록이나 404 화면이 나오면 `index.html`이 있는 폴더에서 서버를 실행했는지 확인하세요.

서버는 내 PC에서만 접속하도록 설정되어 있습니다. 인증서 설치나 크롬 보안 설정 변경은 필요하지 않습니다. Python 서버는 HTML/CSS/JS 파일만 제공하며 API 요청은 크롬에서 HTTPS로 바이낸스에 직접 보냅니다.

### 실제 시세가 들어오는지 확인하기

1. BTC와 ETH가 각각 카드로 표시되는지 확인하세요.
2. **최신 시세 연결됨** 표시, 두 코인의 숫자 가격, 등락률·거래량, **마지막 성공 갱신** 시각이 나타나면 두 코인 모두 유효한 API 응답을 받은 것입니다. 임의 가격은 사용하지 않습니다.
3. 약 30초 기다려 마지막 성공 갱신 시각이 바뀌는지 확인하세요. 가격 자체는 시장 상황에 따라 그대로일 수 있습니다.
4. **새로고침**을 누르면 바로 다시 요청합니다. 첫 요청부터 실패하면 가격은 `—`로 표시됩니다.

이 앱의 ‘실시간’은 30초 간격으로 조회한 최신 가격을 뜻하며, 매 거래를 즉시 전달하는 방식은 아닙니다.

### 연결 문제를 구분해서 확인하기

회사 크롬에서 개별 API 주소가 열린다는 것은 그 주소에 접속할 수 있다는 증거입니다. 하지만 대시보드의 JavaScript 요청에는 브라우저의 교차 출처 접근 정책(CORS)이 추가로 적용되므로 대시보드에서도 확인해야 합니다.

- **디자인만 안 보임:** CSS 로딩 문제입니다. 세 파일을 같은 폴더에 두고 위 서버 명령으로 실행하거나 `preview.html`을 사용하세요.
- **카드는 보이지만 가격이 `—`:** API 오류 안내를 확인하세요. 이는 디자인 문제와 별개입니다.
- 크롬에서 **F12 → Network(네트워크)**를 열고 페이지를 새로고침하세요. `style.css`, `script.js`는 상태 **200**이어야 합니다. `ticker/24hr` 요청을 클릭해 상태와 **Response(응답)**를 확인하세요.
- 대시보드가 사용하는 두 코인 동시 요청도 주소창에서 확인할 수 있습니다: [BTC·ETH API 응답 확인](https://api.binance.com/api/v3/ticker/24hr?symbols=%5B%22BTCUSDT%22%2C%22ETHUSDT%22%5D). 응답에는 두 코인이 모두 있어야 합니다.
- **Console(콘솔)**의 `CORS` 오류는 웹페이지에서 응답을 읽도록 허용되지 않았다는 뜻입니다. `ERR_CERT_AUTHORITY_INVALID`는 해당 브라우저가 인증서를 신뢰하지 못한다는 뜻입니다. 회사 PC에서 발생하면 회사 IT 담당자에게 오류 문구와 API 주소를 알려 주세요.

Codex 내부 Chromium의 인증서 오류는 Codex 개발 환경에서 관찰한 결과입니다. 그것만으로 회사 PC에서도 실패한다고 판단할 수 없습니다. 회사 PC의 실제 크롬 결과를 기준으로 확인하세요. 인증서 검증을 끄거나 보안을 비활성화하는 명령은 사용하지 마세요.

## 화면 읽는 방법

- **현재 가격**: 1 BTC 또는 1 ETH의 USDT 가격입니다. 원화 가격이 아닙니다.
- **등락률**: 최근 24시간의 가격 변화입니다. 상승은 초록색 `+`, 하락은 분홍색 `-`로 표시합니다.
- **24시간 거래량**: 해당 거래쌍에서 거래된 코인 수량입니다(BTC 또는 ETH).
- **거래대금**: 같은 기간 거래된 금액을 USDT로 표시합니다.
- **자동 갱신**: 첫 화면에서 즉시 요청하고, 각 요청이 끝난 뒤 30초마다 다시 요청합니다. 새로고침 버튼으로 바로 갱신할 수도 있습니다.
- **마지막 성공 갱신**: 데이터를 받은 시각이며, 사용 중인 기기의 현지 시간으로 표시합니다.

## 연결 오류가 나타나면

인터넷 연결을 확인한 뒤 **새로고침**을 눌러 주세요. 10초 동안 응답이 없으면 요청을 종료하고 안내를 표시합니다. 오류가 발생해도 30초 후 자동으로 재시도합니다. 이전에 받은 가격이 있으면 그대로 남겨 두고 **이전 시세**임을 알립니다. 데이터가 없을 때는 임의 가격 대신 `—`를 표시합니다.

바이낸스 서비스 장애, 지역별 제한, 회사·학교 네트워크 정책으로 API가 차단될 수도 있습니다. 로컬 서버를 사용해도 이런 제한은 해결되지 않습니다. API 키를 입력하거나 구매할 필요는 없습니다. 요청 한도 안내가 뜨면 반복 클릭하지 말고 잠시 기다려 주세요.

클라우드 개발 환경에서 네트워크 허용 목록을 사용한다면 `api.binance.com` 접근이 필요합니다. 실제 웹페이지의 요청은 **페이지를 연 브라우저의 네트워크**에서 전송됩니다.

## 파일 구성과 수정

| 파일 | 역할 |
| --- | --- |
| `index.html` | 제목, 버튼, 코인 카드 등 화면 구조 |
| `style.css` | 다크모드 색상, 카드 배치, 모바일 화면 디자인 |
| `script.js` | 바이낸스 API 요청, 숫자 표시, 자동 갱신과 오류 처리 |
| `preview.html` | 원본 CSS·JavaScript를 포함한 단일 파일 미리보기(자동 생성) |
| `tools/build-preview.py` | 원본에서 단일 파일 미리보기를 다시 만드는 도구 |
| `README.md` | 실행 방법과 안내 |

문구는 `index.html`, 색상은 `style.css` 맨 위의 색상 변수에서 바꿀 수 있습니다. 갱신 간격은 `script.js`의 `REFRESH_MS = 30_000` 값입니다(밀리초 단위, 30,000 = 30초). 변경 후 저장하고 브라우저를 새로고침하세요. 요청 한도를 피하려면 갱신 간격을 너무 짧게 설정하지 마세요.

## 데이터 출처

바이낸스의 API 키가 필요 없는 공개 주소 `https://api.binance.com/api/v3/ticker/24hr`를 사용합니다. `BTCUSDT`, `ETHUSDT`를 한 번의 요청으로 조회합니다. 차트처럼 보이는 작은 막대 아이콘은 장식이며 실제 가격 차트가 아닙니다. 투자 참고용으로 사용하세요.

## 확인한 테스트와 제한

개발 환경의 Chromium 브라우저에서 준비된 API 응답을 사용해 가격·등락률·거래량 표시, 30초 자동 갱신, 수동 갱신, 연결 오류, 잘못된 응답, 요청 한도, 10초 타임아웃, 이전 시세 유지, 오류 후 복구를 확인했습니다. 모바일 너비(375px)에서 가로 스크롤이 생기지 않는 것도 확인했습니다. JavaScript 문법 검사와 로컬 웹 서버 응답 확인을 통과했습니다.

이전 점검에서는 `data-api.binance.vision`을 사용했고, Codex Chromium의 환경 프록시 인증서 오류로 실제 가격 표시를 확인하지 못했습니다. 현재 버전은 사용자가 회사 크롬에서 접속을 확인한 `api.binance.com`으로 변경했습니다. 변경 후 Codex 명령줄에서는 이 도메인이 네트워크 프록시에서 403으로 차단되어 실제 응답을 확인하지 못했습니다. 사용자의 회사 PC에서 대시보드를 직접 실행한 결과와 CORS 허용 여부는 아직 검증하지 못했습니다. 회사 PC의 개별 BTC API 접속 성공은 사용자가 확인한 결과입니다.

TLS 인증서 검증이나 브라우저 보안을 해제하지 않았습니다. 테스트용 샘플 가격은 앱이나 미리보기 파일에 포함하지 않습니다.

디자인 로딩과 API 실패는 별개입니다. 가격이 `—`로 표시되며 연결 오류 안내가 떠도 카드 디자인은 유지되어야 합니다. 반대로 기본 텍스트만 보이면 CSS 파일 제공 여부 또는 미리보기의 스타일 제한을 확인하세요.

단일 파일 미리보기는 외부 CSS·JS를 404로 응답하게 만든 브라우저 테스트에서도 카드 표시와 스크립트 실행을 통과했습니다. 샘플 API 응답으로 기존 자동 갱신·오류 처리 테스트도 통과했습니다. 사용자 미리보기 서비스 자체는 URL이 없어 검증하지 못했고, 개발용 Chromium의 정책이 `file://` 접근을 차단하여 다운로드 파일 직접 열기도 검증하지 못했습니다. 로컬 HTTP 서버를 통한 실행은 확인했습니다.
